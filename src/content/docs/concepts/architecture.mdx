Seedrail cleanly separates **control orchestration** from **code execution**: the Control Plane can run alongside your local machine or on a dedicated public/intranet server, while every machine holding source code (Execution Host) runs a lightweight user-level daemon that dials outbound to the Control Plane — requiring zero inbound firewall ports, no SSH key distribution, and no third-party relay process.

## Four-Layer Component Topology

Single-machine development stacks and multi-host production deployments share the exact same protocol contract and identity model across four runtime layers:

```text
┌───────────────────────────────────────────────────────────────────┐
│ 1. Clients                                                        │
│    • Web Browser Client           • Seed macOS Desktop (Tauri)    │
└───────────────────┬───────────────────────────────┬───────────────┘
                    │ HTTPS Connect RPC             │ WSS Live Events
                    ▼                               ▼
┌───────────────────────────────────────────────────────────────────┐
│ 2. Control Plane                                                  │
│    • as-control-plane (Go binary: gateway, auth, projects, nodes) │
├───────────────────────────────────────────────────────────────────┤
│ 3. Control Plane Infrastructure (Control Plane side only)         │
│    • PostgreSQL (authoritative state & event persistence)         │
│    • NATS JetStream (real-time delta fan-out buffer)              │
│    • Redis (1-hour single-use host enrollment tokens only)        │
└───────────────────────────────────▲───────────────────────────────┘
                                    │ Outbound WSS (/v1/node/*)
                                    │ Host dials outbound; 0 inbound ports
┌───────────────────────────────────┴───────────────────────────────┐
│ 4. Execution Host (One daemon pair per dev machine / cloud VM)    │
│    • as-workspace-server (parent: tunnel, roots, Git/files/PTY)   │
│    • as-adapter-host (supervised child: drives Claude/Codex CLIs) │
└───────────────────────────────────────────────────────────────────┘
```

| Layer | Where It Runs | Core Responsibilities |
| --- | --- | --- |
| **Web / Desktop Clients** | Browser or macOS desktop app | Renders projects, Git worktrees, file diffs, terminals, and multi-session streams; mutations go over Connect RPC while live deltas arrive on a single WebSocket. |
| **`as-control-plane`** | Local loopback or public/private server | Manages user sessions, project/task state machines, historical event replay, the embedded node gateway (`/v1/node/*`), and installer distribution (`/install.sh`, `/downloads/node/`). |
| **PostgreSQL / NATS / Redis** | Deployed alongside Control Plane only | PostgreSQL is the sole durable source of truth; NATS broadcasts live runtime chunks; Redis atomically consumes single-use host enrollment tokens (even if Redis is temporarily unavailable, already-enrolled hosts continue operating normally). |
| **`as-workspace-server` + `as-adapter-host`** | Each enrolled macOS / Linux host | Runs under the current OS user, listening exclusively on `0600` private Unix sockets inside its state directory with **zero TCP listeners**; handles folder selection, Git worktrees, PTY terminals, local port previews, and Agent CLI protocol adaptation. |

## Five-Level Workspace Model

Seedrail isolates concurrent work across five levels from repository root down to individual execution turns so parallel tasks and agents never step on the same working tree:

<Steps>

1. **Project**
   Bound to an authorized repository directory on a specific enrolled host (`host_id`). Once bound, every file, Git, and terminal operation for that project routes strictly to that host.

2. **Task & Worktree**
   Each task owns an isolated directory or Git worktree with its own branch and uncommitted state boundary, preventing parallel tasks from contending over files.

3. **Conversation**
   An interactive collaboration thread under a task that records user prompts, file references, tool-approval decisions, and turn outputs.

4. **Session & Turn**
   Driven by `as-adapter-host` on the execution host, invoking locally installed coding CLIs (such as Claude Code or Codex) for each turn and streaming normalized runtime chunks back to the Control Plane and clients.

</Steps>

## Outbound-Only Tunnel & Trust Boundaries

Home NAT routers, corporate firewalls, and locked-down cloud security groups typically block inbound connections to developer machines. Seedrail uses an **outbound-only enrollment model** similar to GitHub Actions self-hosted runners:

<Tabs>
  <TabItem label="Outbound Tunnel Lifecycle">
    1. You mint a 1-hour single-use token (`ast_...`) on the Control Plane and run `install.sh` on the target host.
    2. The host exchanges that token at `POST /v1/node/register` for a long-lived **Route Credential** (stored locally with `0600` permissions; the Control Plane stores only its hash digest).
    3. When `as-workspace-server node run` starts, it spawns and health-checks its local `as-adapter-host` child process first, then dials a persistent `WSS /v1/node/control` tunnel to keep the host online.
    4. Whenever the Control Plane needs to read files, open a terminal, or start an agent turn, it signals over the control channel for the host to dial on-demand `WSS /v1/node/data` streams (capped per host at 32 service streams + 8 browser preview streams). Each stream handshake pins a fixed local target (`WORKSPACE`, `ADAPTER`, or `PREVIEW`) rather than permitting arbitrary network dialing on the host.
  </TabItem>
  <TabItem label="Disconnect & Recovery Guarantees">
    - **Turns survive network blips**: Brief disconnects or Control Plane rolling restarts never terminate an in-flight turn on the host; upon reconnect, delivery resumes from event cursors and snapshots without re-running accepted prompts.
    - **Never silently reroutes hosts**: If a project's bound host is offline, requests immediately fail with an explicit `unavailable` status rather than silently dispatching work to a different machine.
    - **Child-process self-healing**: `as-workspace-server` supervises `as-adapter-host` and restarts it with exponential backoff (1s to 30s) if it exits unexpectedly, restoring `READY` without changing host identity.
  </TabItem>
</Tabs>

<Aside type="caution" title="Trust Model">
A Control Plane has full scheduling authority over hosts registered to it (opening terminals and reading/writing authorized directories under the OS user running the node service). Always terminate public Control Plane TLS using a certificate issued by a publicly trusted CA — either directly in `as-control-plane` or on a reverse proxy you fully control — and never place it behind an untrusted TLS-intercepting proxy.
</Aside>
