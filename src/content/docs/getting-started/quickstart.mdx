This guide walks through launching a complete Seedrail stack on a local macOS or Linux development machine — including the Control Plane, Web client, and a local execution host automatically enrolled against your machine — so you can explore multi-worktree and multi-agent workflows right away.

## Prerequisites

Make sure the following tools are installed and available on your `PATH`:

- **Docker** (with `docker compose`, used to start shared local PostgreSQL, NATS JetStream, and Redis containers)
- **Go 1.26+** and **Air** for live reload (`go install github.com/air-verse/air@latest` if not yet installed)
- **Node.js 22+** and **pnpm 10+**
- **PostgreSQL client `psql`** and **`process-compose`**

## Launch in Four Steps

Run all commands from the repository root:

<Steps>

1. **Install workspace dependencies and start shared containers**

   A single set of PostgreSQL, NATS, and Redis containers serves your entire machine; multiple checkouts or Git worktrees automatically isolate themselves by database name, NATS account, and Redis key prefix:

   ```bash
   pnpm install
   make deps-up
   ```

   `make deps-up` waits until all three containers pass health checks and prints default loopback ports (PostgreSQL `15432`, NATS `14222`, Redis `16379`). Run `make deps-status` anytime to inspect container status.

2. **Start the full application stack**

   Choose either background daemon mode or the interactive TUI (the launcher automatically allocates conflict-free ports in `.env` and enrolls your local host):

   <Tabs>
     <TabItem label="Background Mode (Recommended)">
       ```bash
       make dev-detached
       ```
       Once startup finishes, stay in the same terminal to run health checks and mint a login link; run `make dev-attach` anytime to inspect live process logs.
     </TabItem>
     <TabItem label="Interactive TUI">
       ```bash
       make dev
       ```
       Opens the interactive `process-compose` dashboard in the current terminal; run the login command below from a second terminal tab.
     </TabItem>
   </Tabs>

3. **Verify health probes and mint a single-use login URL**

   Verify HTTP readiness for the current stack, then generate a 1-hour single-use login URL:

   ```bash
   make dev-ls
   cp_port=$(sed -n 's/^LOCALDEV_CP_PORT=//p' .env)
   web_port=$(sed -n 's/^LOCALDEV_WEB_PORT=//p' .env)
   curl -f "http://127.0.0.1:${cp_port}/healthz"
   curl -f "http://127.0.0.1:${web_port}/"
   make dev-login
   ```

   Open the URL printed by `make dev-login` in your browser to exchange the one-time token for a session and enter the workspace with your local machine already connected. Re-run `make dev-login` whenever you need a fresh link.

4. **(Optional) Hand off to the macOS Desktop Client**

   If `/Applications/Seed.app` is installed, launch and sign it directly into your local Control Plane:

   ```bash
   make dev-login-desktop
   ```

   <Aside type="tip" title="Custom App Path & Switching Environments">
   If `Seed.app` lives elsewhere, pass `AS_DESKTOP_APP_PATH=/path/to/Seed.app make dev-login-desktop`. If the desktop app is already running, quit it first before running this command to switch Control Plane environments.
   </Aside>

</Steps>

## Lifecycle & Cleanup Commands

Use these commands to pause stacks or clean up isolated branch state:

| Command | Description |
| --- | --- |
| `make dev-ls` | List all registered local stacks on this machine along with status, ports, and checkout paths |
| `make dev-down` | Stop processes for the current checkout while **preserving** its database, NATS cursors, and attachments for future `make dev` runs |
| `make dev-drop` | Stop the current stack and **permanently delete** its isolated database, NATS account, and local state directory (other worktrees are untouched) |
| `make deps-down` | Stop shared PostgreSQL / NATS / Redis containers once no local stacks are running (retains Docker volumes) |
| `make deps-reset` | Stop shared containers and wipe all local Docker volumes (destructive; resets all local development databases on the machine) |
