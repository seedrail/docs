Any developer laptop, office workstation, or cloud VM with your coding toolchain installed can join a Control Plane with a single command — **without `sudo`** (except enabling systemd user lingering once on Linux if disabled), **without opening inbound firewall ports**, and without exposing SSH access.

## Host Requirements

- **Supported platforms**: `darwin-arm64` (Apple Silicon macOS), `linux-amd64`, `linux-arm64`
- **Standard CLI utilities**: `sh`, `curl`, `tar`, and `sha256sum` (or `shasum` on macOS)
- **Network**: Outbound HTTPS reachability to your Control Plane (for example `https://cp.example.com`)

## Generate & Run the One-Line Enrollment Command

Generate an enrollment command either interactively from the Web UI or headlessly via the Control Plane CLI:

<Tabs>
  <TabItem label="From the Web UI">
    1. Sign in to the Web workspace, open **Hosts**, and click **Add Host**.
    2. Enter a recognizable host label (for example `macbook-pro` or `gpu-dev-01`).
    3. Copy the generated one-line command (valid for 1 hour):

       ```bash
       curl -fsSL https://cp.example.com/install.sh | AS_INSTALL_TOKEN=ast_xxxxxxxx sh
       ```

    4. Paste and run it in a terminal on the target machine; the Web UI automatically transitions from waiting to **Connected (READY)**.
  </TabItem>
  <TabItem label="Headless via Control Plane CLI">
    If you have shell access on the Control Plane server, mint an identical one-line enrollment command directly without opening a browser:

    ```bash
    ./as-control-plane host install-command --name gpu-dev-01
    ```

    Run the printed command on the target host. Every `AS_INSTALL_TOKEN` expires after **1 hour**, can be consumed only once, and is passed via environment variable so it never leaks in `ps` / `argv`.
  </TabItem>
</Tabs>

## What `install.sh` Does on the Host

The installer executes six deterministic steps and aborts immediately with a clear reason if any step fails:

<Steps>

1. **Detect OS and CPU architecture**
   Validates `darwin-arm64`, `linux-amd64`, or `linux-arm64` (exits cleanly with `UNSUPPORTED_PLATFORM` without modifying any files otherwise).

2. **Download version-matched binaries and verify SHA-256**
   Downloads `/downloads/node/<os>-<arch>.tar.gz` and its `.sha256` digest from the Control Plane, verifying integrity before unpacking.

3. **Gracefully stop any existing node service**
   Stops an older local node daemon cleanly if one is already running.

4. **Unpack into a user-private directory**
   Installs `as-workspace-server`, `as-adapter-host`, and `as-delegate` into `~/.agent-system/node/bin/` (`0700` permissions) without touching global system paths.

5. **Exchange token for a long-lived Route Credential**
   Runs `as-workspace-server node register --url <cp-origin>`, consuming `AS_INSTALL_TOKEN` and writing the assigned `host_id` and Route Credential into `~/.agent-system/node/state/` (`0600` permissions).

6. **Install and start the user-level background service**
   Runs `as-workspace-server node service install`, capturing your login shell `PATH` and common CLI locations (`~/.local/bin`, `~/.nvm`, `/opt/homebrew/bin`, etc.) so locally installed Claude Code / Codex binaries are discoverable, then launches `node run` to dial the Control Plane.

</Steps>

## Directory Authorization (`--root`) Policy

Nodes enforce **least-privilege directory scoping** to protect private files on your machine:

- **Zero pre-authorization by default**: Running the standard install command above does **not** pre-authorize your machine for agent access. Your OS `Home` directory acts solely as a **read-only browsing root** for the Web folder picker — only specific project subdirectories you explicitly pick and confirm when creating a project are bound and persisted (binding `Home` itself as a project workspace is rejected).
- **Pre-authorizing fixed code roots at install time**: To pre-authorize dedicated workspace roots on a server (such as `/srv/code`), pass one or more `--root` flags via `sh -s --`:

```bash
curl -fsSL https://cp.example.com/install.sh | AS_INSTALL_TOKEN=ast_xxxxxxxx sh -s -- \
  --root /srv/code \
  --root /data/repos
```

<Aside type="tip" title="Updating Pre-Authorized Roots Later">
To update `--root` paths or refresh newly installed CLI `PATH` entries, generate a fresh install command on the Hosts page and re-run it on the same machine with the updated `--root` list (re-running without `--root` preserves previously recorded roots).
</Aside>

## OS Service Supervision

Nodes register as user-level background services tailored to each operating system:

<Tabs>
  <TabItem label="Linux (systemd --user)">
    - **Unit file**: `~/.config/systemd/user/agent-system-node.service`
    - **Boot & logout persistence**: `node service install` automatically runs `loginctl enable-linger "$USER"` so the node comes online at boot and stays running after SSH logout.
    - **Restricted environments**: If unprivileged `enable-linger` is disallowed, the installer exits with code `6` and prints the exact `sudo loginctl enable-linger <user>` command for an administrator to run once before re-running `service install`.
  </TabItem>
  <TabItem label="macOS (LaunchAgent)">
    - **Plist location**: `~/Library/LaunchAgents/io.agentsystem.node.plist`
    - **Launchd domain**: Loads into `gui/<uid>` when run from a desktop terminal or `user/<uid>` over SSH — no `sudo` required.
    - **Lifecycle**: Starts automatically whenever that macOS user logs in; logging out of the macOS GUI account pauses the agent until the next login.
  </TabItem>
</Tabs>

## Day-2 Operations, Upgrades & Uninstall

Manage the local node directly via `~/.agent-system/node/bin/as-workspace-server`:

| Command | Purpose |
| --- | --- |
| `~/.agent-system/node/bin/as-workspace-server node status` | Prints a safe JSON status summary (`host_id`, service IDs, version, and gateway state, with zero secret material) |
| `~/.agent-system/node/bin/as-workspace-server node service install` | Idempotently refreshes the user service definition (re-probing login shell `PATH`) and restarts the node |
| `~/.agent-system/node/bin/as-workspace-server node service uninstall` | Stops and removes OS auto-start while keeping `~/.agent-system/node/` binaries and state |
| `~/.agent-system/node/bin/as-workspace-server node uninstall` | Stops the service and removes `~/.agent-system/node/` completely (never touches your repositories or local Provider logins) |

### Version Upgrades & In-Place Re-Enrollment

- **Smooth upgrades**: When a Control Plane upgrade introduces a major protocol version bump, older nodes report `VERSION_INCOMPATIBLE`. Generate a new install command and run it on the host — as long as `~/.agent-system/node/state/` still exists, the node proves identity with its previous credential, rotates credentials, and **preserves its original `host_id` and all bound projects seamlessly**.
- **Recovering a removed host**: Removing a host in the Web UI immediately closes its tunnel and revokes its credential (the daemon exits cleanly without retry loops). Running a new install command on that machine later revives the original `host_id` in place.
